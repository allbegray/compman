Bring your own release source

Deploy from S3, HTTP, or local — per-profile.

S3 supports prefixes and archives. HTTP and HTTPS accept .tar.gz, .tgz, and .zip archives. Local accepts file:// and bare paths, per-profile deploy lets each profile use a different source, with optional checksum and strategy.

S3-compatible storage

compman deploy --path \
  s3://my-bucket/releases/app.tar.gz \
  --build --tag my-app

Works with AWS S3 and endpoint-compatible services such as Ministack.

Public HTTP / HTTPS

compman deploy --path \
  https://example.com/releases/app.zip \
  --build --tag my-app

Streams the archive with standard TLS verification. Authenticated URLs are not yet supported.

per-profile deploy

# compman.yml
deploy:
  default: s3://my-bucket/releases/app.tar.gz
  dev:
    source: file://./dist/app.tar.gz
  prod:
    source: s3://my-bucket/releases/app.tar.gz
    checksum: sha256:e3b0c4...b855
    strategy: recreate

String form stays valid and is normalized to default. CLI --profile picks the matching entry.

Local + dry-run

compman deploy --path ./dist/app.tar.gz --dry-run
compman deploy --profile prod --strategy pull-only --keep 5

--dry-run verifies checksum and limits, prints a diff, then exits before swapping. pull-only skips builds.

Rollback

compman rollback 20260820_120000
compman rollback --profile prod

Restores backup/.versions/<TIMESTAMP> (kept 3 by default, --keep 1-10). Omit the timestamp for an interactive pick. doctor warns when a profile lacks checksum.

FAQ

Small tool, clear boundaries.

Docker only?

No. compman auto-detects Docker Compose, Podman Compose, legacy docker-compose, and podman-compose.

Where is configuration stored?

A project-local compman.yml describes the stack, Compose files, profiles, managed directories, and optional deploy source.

How are secrets handled?

compman can inject environment variables from AWS Secrets Manager at command time, so secrets never need to live in compman.yml.

Are archive deployments safe?

Archive extraction rejects absolute paths, traversal, and links. Managed-tree replacement rolls back if its file swap fails.

Is there a daemon or server?

No. compman is an on-demand CLI that delegates container operations to the detected local runtime.
